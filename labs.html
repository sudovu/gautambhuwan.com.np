Hardened Nginx Reverse Proxy & HTTP/2 Gateway

OPERATIONAL

Objective: Deploy a secure reverse proxy on Ubuntu Server to terminate TLS 1.3, enforce HTTP/2, sanitize proxy headers, and prevent unauthenticated direct exposure of backend services.

nginx // /etc/nginx/sites-available/production.conf 
server {
    listen 443 ssl http2;
    server_name gautambhuwan.com.np;

    ssl_certificate /etc/ssl/certs/fullchain.pem;
    ssl_certificate_key /etc/ssl/private/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
Problem Diagnosed:

Client IP addresses were being masked by the reverse proxy, resulting in uniform upstream log entries.

Resolution & Takeaway:

Enforcing X-Real-IP and X-Forwarded-For headers allowed backend applications to correctly inspect client origin.

MikroTik Dual-WAN PCC Balancing with Recursive Failover & PCQ QoS

PRODUCTION CONFIG

Objective: Architect a redundant multi-homed edge gateway on MikroTik RouterOS. Implement Per-Connection Classifier (PCC) dual-WAN load balancing, target-scope recursive routing checks to detect upstream ISP backhaul blackouts, and Per-Connection Queue (PCQ) dynamic bandwidth shaping to eliminate bufferbloat.

routeros // edge-gateway-pcc-qos.rsc 
# 1. Multi-Hop Recursive Route Failover via Public DNS
/ip route
add dst-address=1.1.1.1/32 gateway=192.168.1.1 scope=10 comment="Host-Route-ISP1"
add dst-address=8.8.8.8/32 gateway=192.168.2.1 scope=10 comment="Host-Route-ISP2"
add distance=1 gateway=1.1.1.1 check-gateway=ping target-scope=11 comment="Default-ISP1-Recursive"
add distance=2 gateway=8.8.8.8 check-gateway=ping target-scope=11 comment="Default-ISP2-Recursive"

# 2. Firewall Mangle Rules for PCC Load Balancing
/ip firewall mangle
add chain=prerouting dst-address-type=!local in-interface=bridge-lan \
    per-connection-classifier=both-addresses:2/0 action=mark-connection new-connection-mark=ISP1_conn passthrough=yes
add chain=prerouting dst-address-type=!local in-interface=bridge-lan \
    per-connection-classifier=both-addresses:2/1 action=mark-connection new-connection-mark=ISP2_conn passthrough=yes
add chain=prerouting in-interface=bridge-lan connection-mark=ISP1_conn action=mark-routing new-routing-mark=to_ISP1
add chain=prerouting in-interface=bridge-lan connection-mark=ISP2_conn action=mark-routing new-routing-mark=to_ISP2

# 3. Dynamic Bandwidth Fairness via PCQ (Per-Connection Queue)
/queue type
add name=pcq-download kind=pcq pcq-classifier=dst-address pcq-rate=30M
add name=pcq-upload kind=pcq pcq-classifier=src-address pcq-rate=15M
/queue tree
add name=Total-Download parent=bridge-lan queue=pcq-download priority=1
add name=Total-Upload parent=ether1-wan1 queue=pcq-upload priority=1
Problem Diagnosed:

Local ISP gateways remained link-UP during optical upstream fibre breaks, rendering standard default route metric failover useless. Heavy single-user downloads also choked real-time VoIP packets.

Resolution & Takeaway:

Recursive routing with target-scope=11 pings public Anycast DNS through respective gateways, triggering automated reroutes on genuine WAN loss, while PCQ queues dynamically enforce per-host bandwidth limits.

Problem Diagnosed:

Public IPv4 pool exhaustion across growing broadband subscribers, combined with massive centralized syslog storage bottlenecks caused by logging every individual NAT connection translation.

Resolution & Takeaway:

Implemented Deterministic CGNAT (RFC 6598) mapping fixed private IPs to predictable public IP + port block ranges (2,000 ports/subscriber), eliminating 99% of per-session log overhead while securing subscriber traffic behind stateful zone firewalls.
