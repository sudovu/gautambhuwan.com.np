LAB // 001

Enterprise Multi-Area OSPF Topology

VERIFIED LAB

Objective: Design and configure a high-availability multi-area OSPF network with Area 0 (Backbone), Area 1 (HQ Core), and Area 2 (Branch), with inter-VLAN trunking and ABR route summarization to reduce link-state database (LSDB) size.

cisco-ios // abr-router-config.ios 
! Configure Multi-Area OSPF on Area Border Router (ABR)
Router(config)# router ospf 1
Router(config-router)# router-id 1.1.1.1
Router(config-router)# network 10.0.0.0 0.0.0.3 area 0
Router(config-router)# network 192.168.10.0 0.0.0.255 area 1
Router(config-router)# area 1 range 192.168.0.0 255.255.0.0
Router(config-router)# passive-interface GigabitEthernet0/0
Router(config-router)# exit
Router# show ip ospf neighbor
Router# show ip route ospf
Problem Diagnosed:

Frequent SPF recalculations occurred whenever edge switch ports flapped, generating global Type-1 LSAs.

Resolution & Takeaway:

Configuring passive-interface on edge LANs and ABR route summarization contained LSAs within Area 1, stabilizing the backbone.

LAB // 002

Hardened Nginx Reverse Proxy & HTTP/2 Gateway

OPERATIONAL

Objective: Deploy a secure reverse proxy on Ubuntu Server to terminate TLS 1.3, enforce HTTP/2, sanitize proxy headers, and prevent unauthenticated direct exposure of backend services.

nginx // /etc/nginx/sites-available/production.conf 
server {
    listen 443 ssl http2;
    server_name gautambhuwan.com.np;

    ssl_certificate /etc/ssl/certs/fullchain.pem;
    ssl_certificate_key /etc/ssl/private/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
Problem Diagnosed:

Client IP addresses were being masked by the reverse proxy, resulting in uniform upstream log entries.

Resolution & Takeaway:

Enforcing X-Real-IP and X-Forwarded-For headers allowed backend applications to correctly inspect client origin.

LAB // 003

Isolated Microservice Bridge Networks in Docker

VERIFIED LAB

Objective: Create isolated user-defined Docker bridge networks to restrict inter-container discovery and implement persistent storage volumes on Linux.

bash // docker-network-setup.sh 
# Create isolated bridge network with custom subnet
docker network create --driver bridge --subnet 172.28.0.0/16 app_net

# Run isolated container connected only to the defined network
docker run -d --name secure_gateway   --network app_net   --ip 172.28.0.10   -v /var/data/app:/app/data:ro   -p 8080:80   nginx:alpine

# Verify bridge interface on host
ip addr show dev br-$(docker network inspect app_net -f '{{.Id}}' | cut -c1-12)
Problem Diagnosed:

Default bridge network does not provide automatic DNS resolution between container names.

Resolution & Takeaway:

User-defined bridge networks automatically enable built-in DNS service discovery while isolating container traffic.

LAB // 004

Enterprise Campus LAN: HSRP Gateway Redundancy & LACP EtherChannel

VERIFIED LAB

Objective: Deploy a high-availability dual-core campus network with Distribution Switch 1 & 2 (DSW1 & DSW2). Configure Hot Standby Router Protocol (HSRPv2) with interface tracking for seamless gateway failover, bundle multi-link trunks with LACP (802.3ad) EtherChannel, and align Rapid-PVST+ root bridge priority with HSRP active states.

cisco-ios // dsw1-core-redundancy.ios 
! 1. Configure LACP EtherChannel Trunk between Distribution Switches
DSW1(config)# interface range GigabitEthernet0/1 - 2
DSW1(config-if-range)# channel-group 1 mode active
DSW1(config-if-range)# exit
DSW1(config)# interface Port-channel 1
DSW1(config-if)# switchport trunk encapsulation dot1q
DSW1(config-if)# switchport mode trunk
DSW1(config-if)# switchport trunk allowed vlan 10,20,99

! 2. Configure HSRPv2 with Priority, Preemption & Uplink Tracking
DSW1(config)# interface Vlan10
DSW1(config-if)# ip address 192.168.10.2 255.255.255.0
DSW1(config-if)# standby version 2
DSW1(config-if)# standby 10 ip 192.168.10.1
DSW1(config-if)# standby 10 priority 110
DSW1(config-if)# standby 10 preempt
DSW1(config-if)# standby 10 track GigabitEthernet0/0 20
DSW1(config-if)# exit

! 3. Align Spanning Tree Root with HSRP Active Node
DSW1(config)# spanning-tree mode rapid-pvst
DSW1(config)# spanning-tree vlan 10 root primary
DSW1(config)# spanning-tree portfast default
DSW1(config)# spanning-tree portfast bpduguard default
DSW1# show standby brief
DSW1# show etherchannel summary
Problem Diagnosed:

Uplink loss on primary DSW1 resulted in blackholed traffic because downstream access switches continued forwarding packets to DSW1 due to static default gateway pointers.

Resolution & Takeaway:

Configuring HSRP interface tracking (standby 10 track Gi0/0 20) with preemption immediately reduced DSW1's priority from 110 to 90, triggering seamless sub-second failover to standby DSW2.

LAB // 005

Route-Based Site-to-Site IPsec VTI VPN with Dynamic BGP

OPERATIONAL

Objective: Establish an encrypted route-based IPsec Virtual Tunnel Interface (VTI) between Corporate HQ (AS 65001) and Remote Branch (AS 65002) over an untrusted WAN. Configure hardened IKEv2 cryptographic suites, enable Dead Peer Detection (DPD), and establish dynamic eBGP routing for zero-touch subnet convergence.

cisco-ios // hq-vpn-vti-bgp.ios 
! 1. Hardened IKEv2 Proposal & Keyring
crypto ikev2 proposal IKEV2-SEC-PROP
 encryption aes-gcm-256
 prf sha256
 group 19
crypto ikev2 policy IKEV2-POLICY
 proposal IKEV2-SEC-PROP
crypto ikev2 keyring BRANCH-KEYRING
 peer BRANCH-ROUTER
  address 203.0.113.2
  pre-shared-key SuperSecretVpnKey2026

! 2. IPsec Profile & Virtual Tunnel Interface (VTI)
crypto ipsec transform-set TS-GCM esp-gcm 256
 mode transport
crypto ipsec profile IPSEC-VTI-PROF
 set transform-set TS-GCM
 set ikev2-profile IKEV2-PROFILE

interface Tunnel0
 ip address 10.255.255.1 255.255.255.252
 ip mtu 1400
 ip tcp adjust-mss 1360
 tunnel source GigabitEthernet0/0
 tunnel destination 203.0.113.2
 tunnel mode ipsec ipv4
 tunnel protection ipsec profile IPSEC-VTI-PROF

! 3. Dynamic eBGP Peering across Encrypted Tunnel
router bgp 65001
 neighbor 10.255.255.2 remote-as 65002
 neighbor 10.255.255.2 timers 5 15
 address-family ipv4 unicast
  network 192.168.10.0 mask 255.255.255.0
  neighbor 10.255.255.2 activate
HQ-RTR# show crypto session detail
HQ-RTR# show ip bgp summary
Problem Diagnosed:

Legacy policy-based IPsec crypto maps required continuous manual ACL edits on both ends whenever new subnets were provisioned, and 1500-byte packets caused silent fragmentation packet drops.

Resolution & Takeaway:

Route-based VTI provides a clean virtual interface supporting multicast and dynamic BGP routing, while ip tcp adjust-mss 1360 completely resolved TCP window fragmentation drops.

LAB // 006

MikroTik Dual-WAN PCC Balancing with Recursive Failover & PCQ QoS

PRODUCTION CONFIG

Objective: Architect a redundant multi-homed edge gateway on MikroTik RouterOS. Implement Per-Connection Classifier (PCC) dual-WAN load balancing, target-scope recursive routing checks to detect upstream ISP backhaul blackouts, and Per-Connection Queue (PCQ) dynamic bandwidth shaping to eliminate bufferbloat.

routeros // edge-gateway-pcc-qos.rsc 
# 1. Multi-Hop Recursive Route Failover via Public DNS
/ip route
add dst-address=1.1.1.1/32 gateway=192.168.1.1 scope=10 comment="Host-Route-ISP1"
add dst-address=8.8.8.8/32 gateway=192.168.2.1 scope=10 comment="Host-Route-ISP2"
add distance=1 gateway=1.1.1.1 check-gateway=ping target-scope=11 comment="Default-ISP1-Recursive"
add distance=2 gateway=8.8.8.8 check-gateway=ping target-scope=11 comment="Default-ISP2-Recursive"

# 2. Firewall Mangle Rules for PCC Load Balancing
/ip firewall mangle
add chain=prerouting dst-address-type=!local in-interface=bridge-lan \
    per-connection-classifier=both-addresses:2/0 action=mark-connection new-connection-mark=ISP1_conn passthrough=yes
add chain=prerouting dst-address-type=!local in-interface=bridge-lan \
    per-connection-classifier=both-addresses:2/1 action=mark-connection new-connection-mark=ISP2_conn passthrough=yes
add chain=prerouting in-interface=bridge-lan connection-mark=ISP1_conn action=mark-routing new-routing-mark=to_ISP1
add chain=prerouting in-interface=bridge-lan connection-mark=ISP2_conn action=mark-routing new-routing-mark=to_ISP2

# 3. Dynamic Bandwidth Fairness via PCQ (Per-Connection Queue)
/queue type
add name=pcq-download kind=pcq pcq-classifier=dst-address pcq-rate=30M
add name=pcq-upload kind=pcq pcq-classifier=src-address pcq-rate=15M
/queue tree
add name=Total-Download parent=bridge-lan queue=pcq-download priority=1
add name=Total-Upload parent=ether1-wan1 queue=pcq-upload priority=1
Problem Diagnosed:

Local ISP gateways remained link-UP during optical upstream fibre breaks, rendering standard default route metric failover useless. Heavy single-user downloads also choked real-time VoIP packets.

Resolution & Takeaway:

Recursive routing with target-scope=11 pings public Anycast DNS through respective gateways, triggering automated reroutes on genuine WAN loss, while PCQ queues dynamically enforce per-host bandwidth limits.

LAB // 007

Hierarchical IPv4/IPv6 VLSM Engine & IPAM Architecture

REFERENCE BLUEPRINT

Objective: Engineer an enterprise-grade hierarchical IP address allocation scheme for a multi-tier enterprise network from a single 172.16.0.0/23 supernet block (512 total addresses) and dual-stack 2001:db8:acad::/48 IPv6 global unicast assignment. Maximize host density via Variable Length Subnet Masking (VLSM), eliminate broadcast spillover, preserve address space for expansion, and maintain clean contiguous route summarization boundaries.

cisco-ios // core-router-vlsm-subinterfaces.ios 
! Core Gateway 802.1Q Subinterface & Route Summarization Configuration
Core-RTR(config)# ipv6 unicast-routing

! Engineering Subinterface (VLAN 10)
Core-RTR(config)# interface GigabitEthernet0/0/0.10
Core-RTR(config-subif)# encapsulation dot1Q 10
Core-RTR(config-subif)# ip address 172.16.0.1 255.255.255.128
Core-RTR(config-subif)# ipv6 address 2001:db8:acad:10::1/64
Core-RTR(config-subif)# exit

! Guest Wi-Fi Subinterface (VLAN 50)
Core-RTR(config)# interface GigabitEthernet0/0/0.50
Core-RTR(config-subif)# encapsulation dot1Q 50
Core-RTR(config-subif)# ip address 172.16.1.1 255.255.255.128
Core-RTR(config-subif)# ipv6 address 2001:db8:acad:50::1/64
Core-RTR(config-subif)# exit

! Single Contiguous OSPF Route Summarization towards WAN Core
Core-RTR(config)# router ospf 1
Core-RTR(config-router)# area 1 range 172.16.0.0 255.255.254.0
Core-RTR(config-router)# exit
Core-RTR# show ip route summary
Problem Diagnosed:

Legacy flat /24 subnet assignments exhausted private address pools rapidly while incurring >85% host address waste on small P2P and server networks, and resulted in fragmented routing tables.

Resolution & Takeaway:

Structuring subnets in descending order of host requirements fit 6 distinct department VLANs plus WAN point-to-point transit circuits inside a single compact 172.16.0.0/23 block, allowing instantaneous upstream route summarization.
